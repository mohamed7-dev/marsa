# UI Component Library & Design System

## Design System Architecture

- The design system is a browser-oriented port of the GNOME libadwaita stylesheet.
- The port removes GTK-specific constructs and other behavior that has no browser equivalent while translating widget and layout styles into generated Sass.
- The package owns both the shared stylesheet design system and the browser UI component library. Keep it independent of `@marsa/core`.
- Compiled global tokens, shared classes, and per-widget Lit style modules are emitted under `src/styles/`. CSS files are not package exports.

## Upstream and generated sources

- `scripts/fetch-upstream.mjs` shallow-clones or updates GNOME/libadwaita in `src/design-system/upstream`.
- `scripts/port.mjs` reads `src/design-system/upstream/src/stylesheet` and writes generated Sass into `src/design-system`. An optional checkout path can be passed to the script.
- Files generated by the port script must not be edited by hand; make changes in the porting script and regenerate them.
- `scripts/build.mjs` compiles `tokens.scss` to `src/styles/tokens.css`, `shared.scss` to `src/styles/common.css`, and each widget/layout Sass partial to a Lit style module in `src/styles/components/`.
- All Sass sources, including `src/design-system/index.scss` and `src/design-system/tokens.scss`, belong under `src/design-system`.
- `tokens.scss` defines the global custom properties and color-scheme metadata emitted to `src/styles/tokens.css`.
- `shared.scss` imports shared Sass helpers and classes from assets, icons, drawing, and common sources. Its CSS output is optional for widget Shadow DOM and must not contain global token selectors.
- Widget and layout Sass partials are compiled into separate Lit modules under `src/styles/components` and belong only to their component's Shadow DOM.
- Hand-written `_icons.scss` maps symbolic Sass icons used by ported styles; `_assets.scss` embeds the upstream SVG assets through `asset-url()`. Do not add a runtime icon registry unless requested.
- `scripts/check.mjs` verifies token-only and shared-class stylesheet boundaries and generated component style modules.
- `scripts/check.mjs` parses the compiled CSS and checks for GTK-specific leftovers.
- Run `pnpm sync:adwaita` from this package to fetch, port, build, and check the upstream stylesheet.

## Tooling

- Package linting covers both `src` and `scripts`. The scripts run in Node.js; their Node globals are configured in the root ESLint flat config.
- Keep script paths anchored to the script/package location rather than relying on the caller's working directory.
- Always prefer Lit and native Web Components, HTML elements, CSS, and browser APIs when implementing UI components. Do not add third-party component-library dependencies.
- For implementation patterns and best practices, consult the Web Awesome source at [github.com/shoelace-style/webawesome](https://github.com/shoelace-style/webawesome) as a reference only. Learn from its component structure, accessibility, lifecycle, and testing approaches; adapt ideas to Marsa's Lit/native architecture instead of copying components or mapping its APIs one-to-one.
- Build on native controls for their built-in keyboard, focus, navigation, disabled, and accessibility behavior. When a custom element wraps a native control, preserve and explicitly test those behaviors rather than recreating them with non-semantic elements. Do not claim form association unless the custom element implements and tests the form-associated custom element contract.
- Do not import or re-export another component system, its icon utilities or registries, React adapters, or dependencies.
- Keep package exports tree-shakeable. Declare only the side-effectful module entry points needed for custom-element registration in `package.json`; avoid aggregating unrelated modules into component entry points.
- Expose Marsa components as `marsa-{component}` custom elements. Name each component after its libadwaita counterpart.
- Implement Marsa-prefixed Lit custom elements as the stable public API. The component owns Marsa-specific styling, properties, events, slots, and accessibility behavior.
- Match the corresponding libadwaita component's visual design and interaction semantics using the shared design-system styles and tokens. Preserve accessible names and roles, keyboard behavior, focus handling, disabled/selected states, reduced motion, and RTL behavior; do not rely on visual styling alone to provide behavior.
- Keep components independent of `@marsa/core`; integrations with kernel/runtime behavior belong in the appropriate adapter package.
